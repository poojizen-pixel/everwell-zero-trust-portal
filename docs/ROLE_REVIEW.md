# Role-by-role review of the portal (Doctor, Nurse, Receptionist, Security administrator)

Academic demonstration, synthetic data only. This document records a review that did **not** assume the roles were right because the earlier regression tests passed. Status words: **implemented** (code), **compiled**, **tested** (an executed test row passed), **demonstrated** (shown by hand), **NOT RUN**.

**Update (interface redesign, 2026-10-12, same day):** the screens were redesigned in place (see `docs\UI_DESIGN.md`) and this review was re-run against them. The page inventory (`role_ui_inventory.mjs`) and the UI rows UI1-UI7 were rewritten for the new screens, the receptionist gained appointment management (finding 15), and the administrator's screens no longer show raw device identifiers (finding 16). Section 4 is the matrix generated from the final run after the redesign; sections 2 and 3 keep the findings of the first pass and add the new ones.

**Update (role-specific interfaces, 2026-10-13):** the status strip, the session screen and the demonstration screen were removed from the clinical workspaces, the security console was given evidence, times and an exact state vocabulary, the server now answers a missing patient number like an unassigned one and stops sending security figures to roles that do not need them. Findings 18-24 below are new, three rows of section 3 changed, and the matrix of section 4 was regenerated. The full audit is `docs\ROLE_UX_AUDIT.md`; the new test groups are **X** (authorization matrix, need-to-know, no existence oracle) and **RU** (role-specific interfaces in real Chrome).

## 1. How it was reviewed

| Layer | What was inspected | How |
|---|---|---|
| UI | every screen of the navigation, panel, table header, field label, button, input and badge each role sees, the patient views (listed patients and ids the list does not offer), the emergency dialog and the reschedule dialog | headless desktop Chrome signs in as each role and clicks through (`tests\e2e\role_ui_inventory.mjs`; asserted by UI1-UI7) |
| Frontend requests | every request each page made and the fields of every answer | recorded by the same run (DevTools network events) |
| Server handlers | `GatewayHandler`, `Decider`, `ScopeService`, `Decision` (PDP); `Access`, `PatientDetailHandler`, `PatientsListHandler` (protected app); header handling of the C++ PEP | read in full |
| API responses | the response fields each role receives from every endpoint, restricted fields and actions, tampering with query, body, headers, verbs and paths | group R of `tests\e2e\run_e2e.ps1` (direct calls through the PEP) |
| Database access | `role_permissions`, assignments, stored columns; which sources name clinical or encrypted columns | read-only SQLite probe of the run database (`db_probe.mjs`), SQL read in code, static check R19 |
| Defence in depth | the protected app on its own, called with correctly signed but wrong or hostile identity claims (a misbehaving PEP) | `tests\e2e\app_direct.mjs` |
| Emergency (break-glass) access | scope, permitted actions, duration, session binding, input validation | rows BG1-BG6 and AP7 |

Before any change, the new tests were run against the **unfixed** build: 15 rows failed (each one a confirmed finding below). After the fixes the same tests pass, so every fix has a mutation proof.

## 3. Observations that were deliberately NOT changed

| Item | Why |
|---|---|
| The doctor's export returns synthetic SSN and billing | it is the demonstration of the top sensitivity tier (assigned patients only, step-up PIN, never under emergency access); remove it for any real use |
| While the evaluation tools are enabled (the default in this academic build) denial bodies and `/ctl/session` still carry the risk score, session risk, scoring breakdown, posture signals and addresses for every role | the demonstration needs them in evaluation mode; with the tools off the server withholds them (X9, X10). Recommended off outside a demonstration |
| The "Demonstration tools" screen still exists for the three non-administrator roles, but only in evaluation mode (page opened with `?evaluation=1` and the evaluation tools enabled) | it is the evaluation aid that shows the server refusing direct calls and the real decision after a simulated posture or network change; it adds no access and is invisible in the normal workspace (RU11) |
| `/ctl/session` still returns the full policy to the administrator | redundant with `/admin/policy`, harmless for that role |
| Clinical columns are stored in plain text in the database (SSN and billing are encrypted) | synthetic data; encryption at rest of every column is out of scope for the demo |
| Over the USB route all requests reach the edge from the laptop's loopback address | the server cannot tell phone from laptop by address; use "This browser" on the phone |
| Break-glass justification is free text that administrators read | the dialog now warns doctors not to write clinical details |
